<!-- Rhea's answers, each with the question it answered and the date. -->
- **Ship the window fix on its own first (Rhea, 2026-11-17):** asked whether to ship the stacked-windows fix with this close-out pass as 0.37.1 and then build release 4 of the reactions pass (would drop to 0, and saves) as 0.38.0, or fold it into 0.38.0, she chose "Ship 0.37.1 first (Recommended)". So this chat's lock first said 0.38.0 (its record was removed unbuilt) and now says 0.37.1.
- **The bug (found live 2026-11-17 in the close-out pass, on installed 0.37.0):** a Skeleton Guard's Strike at Test Hero asked his Blazing Spirit and Deflecting Wave in two windows opened on the same spot, with the champion's Glimpse of Redemption a third; the lower window couldn't be seen or clicked (a real click timed out on it), so Blazing Spirit ran out of time. That breaks the 0.36.0 decision "one window per character and moment". Cause: the damage gate gave every row its reaction's own `group`, which is meant for a champion's pick of ally. Fixed: `harmGroup` (react.mjs) keeps a group only for a reaction that protects someone else (and Scintillating Safeguard's one row); a reactor's own rows share its window, "You have one reaction. Use one?" with a button each; the Moment A to C rows carry their numbers as `detail` so the shared window shows them under each name (they also show now on the GM's row); and any second question window open at the same time steps 40 px down and right, so a champion's ally window beside the player's own question can't hide it.
- **Interposing Earth for a Strike at someone else (u-126, settled 2026-11-17):** not a bug. Its trigger is "You are the target of a Strike or would attempt a Reflex save against a damaging area effect" (read from PF2e's compendium in PF2 Test), and `fits` asks it of the target only (`target: true`); 0.37.0's live round shot at Test Hero, not at the animist. A shortbow Strike at the animist itself asked it (see r-27).

## Review
<!-- The independent reviewer's findings, each marked verified true or false and what was done.
     Required when code changed; otherwise write `waived by Rhea <date>` with her reason. -->
An independent agent read the code diff, this record's Decisions, the prompt and `show` in ui/react.mjs, `harmGate`, `askReactions` and `rx3Facts` in fight.mjs and the reaction rows of ui/turns.mjs (4 findings, 2026-11-17, code read only). Each checked against the code:
- 1 verified true (by reading; not provable without the race): the 40 px step counted rendered windows after each `await render`, and the windows of one question start together, so both could count the other and move alike. Fixed: the place is counted from the open windows before `open.set` and the render (the calls run synchronously up to their first await, so the first counts 0 and the second 1).
- 2 verified true: a Pause row's detail is "then make it yourself", which the shared window printed under its name beside a button that says it again, and the new `detail` also reached the GM's row in the player's second person ("your armor is broken"). Fixed: the numbers go on the row as `numbers` (read only by the player's shared window), never for a Pause row; the GM's row is as it was.
- 3 verified true: the note's filter that hid a champion's unpicked rows relied on `group`, so a character's own unused rows now read "…'s Deflecting Wave was skipped". Fixed: a row skipped because the same creature used another reaction is left out of the note, whatever its group (the attack and hit moments benefit too).
- 4 verified true: Scintillating Safeguard always kept a group of its own, so with Eat Fire beside it the caster still got two windows. Fixed: it keeps a group only when its row is for an ally (`harmGroup`: the reactor isn't the damaged one); the one-row check matches by reaction and reactor instead of by group. Unit check updated.
