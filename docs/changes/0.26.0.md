An independent reviewer that hadn't seen the design talk read the diff of every script, the two new files, this record and the bands doc in full (about 65,000 tokens; it listed what it read in part and what it didn't: the Monster Minds window outside the diff, `sense`, `sideOf`, the extend functions, the unit tests and six of the touched docs). Nothing was run in Foundry by it. 14 findings; each checked by Angel in the code:
1. **A leader built asleep was told to its band as fallen** (`fallenWord` used `isDown`, which counts Unconscious). True. Fixed: down is 0 HP or Dying; asleep is not fallen, for the leader and for next in line. A trap in the bands doc.
2. **Bands made on a map with no brief vanished once the map got a brief.** True. Fixed: `bandsOf` reads both homes (the brief's wins a shared key), each band is written back where it lives, `removeBand` clears both, and a band moves into the brief when a build row joins it.
3. **A hand-placed leader taken out of its band left its mark behind; `join` with a built token did nothing and said nothing.** True. Fixed: the mark and a kind's job go with the monsters that leave; a built token is refused with the reason.
4. **A leader mark or a job pointing at a row of another band survived cleaning.** True. Fixed in `briefBands`, with a unit test.
5. **An open Build window with a row added wrote stale bands back.** True. Fixed: the scene's bands are always taken; each row still the scene's takes its band. What is left (marks pointing at the wrong row of the same band after rows moved in the middle) is an Open item in the bands doc.
6. **A long band name gave two different keys.** True (39 letters then " b c"). Fixed: the trailing dash is cut in `bandId`; a unit test.
7. **`letGo` now runs inside `runTurn` for a band let go as a whole** (the current combatant deleted while the request is still running). Not decidable by reading: fl-11 checks that the next creature's turn starts once and isn't skipped, on Auto and off.
8. **A job's kind name (a brief row's name) went into the packet ungated.** True. Fixed: it goes through the name gate; a unit test.
9. **A fallen GM-hidden leader was still announced, and a hidden successor hinted at.** True. Fixed: a leader the GM has hidden is never reported fallen (one that got away is); hidden members aren't next in line. An Open item says the band isn't told if a hidden leader dies.
10. **Angel's pick of a leader moves on when the fallen leader's token is deleted.** True, and left: an Open item (a marked leader reads "gone").
11. **An old `leader: true` row in a chat's brief became a GM's mark.** True. Fixed: only a chat could write that mark, so it is Angel's; a unit test.
12. **`bands.set` with a mistyped key made an empty band.** True. Fixed: a new band needs a name.
13. **Hand-placed monsters join token by token, but the page showed the first token's band for the kind.** True. The select now says when only some are in a band; the rest is an Open item.
14. **Docs against the code:** `minds: 1` in the minds doc (fixed); "never read from the token's copy" (reworded: tokens the standing build doesn't know go by their own flag); "a hard cap of 3,600" (reworded: the per-line caps bound it and a unit test checks the largest); this record's empty sections (filled since).
