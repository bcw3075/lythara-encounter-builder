## Review
<!-- The independent reviewer's findings, each marked verified true or false and what was done.
     Required when code changed; otherwise write `waived by Rhea <date>` with her reason. -->
An independent agent read the diff and the docs (no live testing); 9 findings, each checked against the code:
1. A Stride after a Climb could go with Foundry's climb action (`moveAction` didn't list climb): **true** as code (live the token's action read `walk` after the Climb); fixed, climb added.
2. A Fly off a tree to a square still beside the trunk kept the climbing flag, Off-Guard and `clinging`: **true**; fixed, `runStride` clears the flag after a Fly that moves.
3. A Climb didn't end Take Cover at run time (`endsCover` knew only ground moves), though `checkPlan` said it does; same gap for a Fly changing height on its own square since 0.13.0: **true**; fixed in `endsCover`, unit-tested.
4. A reload during a critical failure's fall went on with no note: **true**; fixed, `nextClimb` asks when `falling` has no `fell`, the note says what to apply, the history line says "not confirmed".
5. A failed Climb (no progress) with steps after it didn't re-plan, though the prompt says so: **true**; fixed, it re-plans (`noClimb`) like a Stride stopped short.
6. A dead climber stayed in the air (`clinging` before `dead`; `settleClimbers` left the body up); a token with no actor could throw in `setClimbing`: **true**; fixed: the dead drop, the actor guarded, each token in its own try.
7. Off-Guard edge cases: a shared Off-Guard from another cause ending, the GM deleting the module's, a reload between `setClimbing` and its record re-planning for its own Off-Guard: **true**; fixed: `settleClimbers` puts Off-Guard back at the turn change, a stale guard id is replaced, the "arrived" baseline leaves its own Off-Guard out.
8. Two held items with one slug renumber after one is Released: **true but harmless** (a mismatched id is refused and re-planned; a reload asks), left as is; the prompt's "10 ft at 40 or more" understated 60 ft: fixed.
9. The file header didn't name Climb and Release; with no route a Climb said "no tree beside it": **true**; both fixed.
The reviewer's open question, whether Foundry lets a creature with no climb Speed use the `climb` movement action, was answered live in mv-16 (yes; filed in Traps).
