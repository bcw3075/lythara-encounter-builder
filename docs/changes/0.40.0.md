Fixed: `endTurn` leaves a `saves` or `fled` request to that sweep, as the tracker's Next turn does.
2. **False in effect: an away player's character in monster-only paths.** Every caller of `runnable` was read: the turn hooks also need the `run` tick; the group rows leave out anything with a player owner (`tickRows`'s `party`); `keepsBook` needs no player owner; yields, commands and band orders are about monsters and their allies, never a player's character. The speak box can show on its unticked turn, as for a party member the GM plays.
3. **True: a leftover tick could play a logged-in player.** If no runner page saw the login, `standIn` stayed true through the `run` flag. Fixed: `standIn` is now "no owner online, or `back.pending`" (Angel finishing the turn already under way); a missed login now simply stops Angel.
4. **True: a login during a turn's settle wait.** `onTurnChange` checked the tick before `settle`. Fixed: it checks the tick and `runnable` again after the settle and scene waits.
5. **False: End turn from any GM.** `playMyself` and `doIt`'s refusals write the request from any GM page the same way; End turn's guard reads the round, the combatant and the steps left after the confirm.
6. **False: a late plan after End turn.** A plan is taken only for a request still `requested` (the existing contract, `docs/features/brain.md`); `onTurnChange` already rechecks the round and combatant after its waits.
7. **False: Fable naming.** `modelFor` checks `MODELS.includes(pick)` and `modelName` reads `MODEL_WORDS` and the id pattern; rt-17 passes in the unit run.
8. **True, minor: a model pick left on a character.** Fixed: `untickParty` clears `modelPick` with the ticks.
9. **False: `back` left behind.** `untickParty` runs on `deleteCombat` (`docs/features/turn-loop.md`), so a combat ending mid-turn clears it.
10. **True, low: "Open" could lag "Shown".** Fixed: the main window redraws after the party window's render settles.
11. To check: `pro` with no forms uses its default (`forms = IT`, read: true); whether `user.active` is already updated when `userConnected` fires is checked live (cu-7).
12. **Found in the live test of the first test build (not by the reviewer), fixed in the second:** the turn box said "Sonnet 5.5 (yours)" for a monster she had set to Fable while the installed bridge (0.4.1) still sent Fable to Sonnet; it now says "Sonnet 5.5 (you picked Fable: the bridge used this)", and "(yours)" only when the model used is her pick.
