## Review
An independent reviewer (a separate agent that hadn't seen the work) read the diff, this record and the feature docs on 2026-11-08, with no live access. Each finding was checked against the code:
1. A flier that Delays falls anyway (`runDelay` records `ended` and moves the turn on before `delayed` is saved). **Verified true** (fight.mjs `runDelay`: `record({ ended })`, `nextTurn`, then `delayed` saved at the end of the step). Fixed: `shouldFall` reads the Delay step's log; unit test.
2. A Fly begun before a reload doesn't count as flying. **Verified true.** Fixed: `started` counts; unit test.
3. Turns the GM played or stopped without pressing Play it myself would still make it fall. **Verified true** (only `manual` was skipped). Fixed: only after a turn the module ran to `done`; unit test over manual, stopped, ready, held, requested.
4. A dead flier never comes down, against the doc. **Verified true.** Fixed: the body drops with no roll (`drop`); unit test; doc corrected.
5. Any creature up high counts as flying (a ledge). **Verified true.** Fixed: "in the air" needs a fly Speed, for the refusal and the fall; unit test.
6. A GM-set height off the 5-ft steps (7 ft) can't hover. **Verified true.** Fixed: the height it has is always accepted; unit test.
7. Area spells ignore height. **Verified true** (`area.mjs` has no elevation). Fixed: `verticalGap` in `caughtBy`; unit tests; areas doc Decision and check ar-8.
8. A reload mid-fall leaves no trace; the note may not show. **Verified true for the reload.** Fixed: the first save carries a "falling" note. The note-visibility part is moot now that only `done` turns fall (`latestNote` shows those).
9. Stepping the tracker back could make a creature fall. **Verified true** (no direction check). Fixed: `movedOn`; unit test.
10. The fall's rolls follow the runner's roll mode, so could be whispered. **Verified true.** Fixed: `rollMode: "publicroll"` on both. The same gap elsewhere in fight.mjs is not changed here (open item in turn-loop? recorded below under Unverified).
11. Arrest a Fall ignores a reaction already used. **True;** recorded as an open item (reactions aren't tracked yet).
12. Fall damage ignores the monster-damage setting. **True and intended** (it is the monster's own damage); written into the code comment and moves.md.
13. Rising straight up doesn't end Take Cover. **Verified true.** Fixed: any change of height ends it, a hover doesn't; moves.md Decision.
14. An off-grid flier changing height snaps to its grid square. **True;** recorded as an open item.
15. The history shows Foundry's booked cost for a Fly. **True,** labelled "charged" already; recorded in moves.md How it works. No change.
16. A rising diagonal is priced as a diagonal into difficult terrain. **True and intended** (that is how difficult terrain prices a diagonal); no change.
17. The fall's decision and the stop-short height had no tests. **True.** Fixed: pure `shouldFall`, `movedOn` (turn.mjs) and `heightWhenCut` (move.mjs) with unit tests.
Checked fine by the reviewer: hook bodies, nothing secret added to the packet, no re-plan for its own height, a Fly never sent twice after a reload, a fall never applied twice.

- Foundry prices height as a plain third axis, so flying's height is priced by the module: `docs/features/moves.md` Traps, and unit tests for `heightCost`.
- `Combat#previous` must be read before anything awaits; a token's `movementAction` sticks at `fly`: `docs/features/moves.md` Traps.
- Delay moves the turn on before its request says so (review finding 1): `docs/features/moves.md` Traps.
- The gate counted an untouched Review section as filled and as "waived by Rhea": the template's two-line hint was read as content. Fixed in foundry-mod-tools (comments removed whole before a section is read), with a test that fails on the old gate (commit a78d2ef).
