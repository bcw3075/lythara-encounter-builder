## Review
<!-- The independent reviewer's findings, each marked verified true or false and what was done.
     Required when code changed; otherwise write `waived by Rhea <date>` with her reason. -->
- Independent reviewer (a separate agent that hadn't seen the work) read the diff, the record and the feature docs; 9 findings, each checked in the code:
  1. verified true (bug): a party member's token has no group, so `tacticsFor` gave it the whole Tactics page, the monsters' plans. Fixed: `tacticsOf` gives the party's side nothing.
  2. verified true: abilities came only from `action` items; a character's actions are mostly feats. Fixed: a character's feats that are actions, free actions or reactions are included.
  3. verified true in part: a character's Strikes included unready ones (fixed: ready and visible only, NPCs unchanged); a character's refused shot under Ranged Combat stopping the turn instead of re-planning can't be judged without a live test (u-45).
  4. verified true: a familiar or a player's companion as an ally kept its name. Fixed: only an NPC no player owns goes by name.
  5. verified true: the `run` flag stays on the token, so a party member ticked once would come up ticked next fight. Fixed: `untickParty` clears its ticks when the fight is deleted (Rhea: default unticked).
  6. verified true: a dying or unconscious party member would get a request every plan for which is refused. Fixed: no request; its turn is the GM's.
  7. verified true: a Burrow dipping from the surface that stopped short mid-plan was a counted re-plan before and became uncounted. Fixed: uncounted only when it started below; the doc says so.
  8. verified true: "(party)" (any character no player owns) and the side (alliance) could disagree for a villain built as a character. Fixed: a party member must be on the party's side.
  9. verified true (nit): labels last the fight, so "E1, E2" in the prompt read as if E meant an enemy. Fixed: the prompt says the letter means nothing about sides.
