## Review
<!-- The independent reviewer's findings, each marked verified true or false and what was done.
     Required when code changed; otherwise write `waived by Rhea <date>` with her reason. -->
- One independent review (a general-purpose agent that hadn't seen the work; reading list: both diffs (module scripts, unit tests and feature docs; the bridge whole), `docs/features/api-route.md` and this record; about 238,000 tokens read). 13 findings, each checked against the code; all 13 true and all fixed:
  1. (true, the worst) Two thinkers could plan one turn: an event stays live while its request waits, so a turn a chat took while the API's light was off went to the API too a few seconds later, a slow API answer let its light lapse and the chat take the turn, and `submitPlan` accepts a plan over a ready one. Fixed: `waitForEvent` stamps `thinker` on the request and renews that thinker's light; `whoGets` keeps the turn with it while it listens or for `HOLD_MS`; `offRoute` ignores the other thinker's plan; the worker renews its light every 30 s while it waits on the API (`route.alive`); per-request timeout down to 60 s.
  2. (true) A hand-in that threw, timed out or was turned down without a retry event left the turn with nobody on it. Fixed: the worker hands on any answer that didn't land, wasn't refused with a try left and wasn't ignored on purpose (a bridge test makes the hand-in throw).
  3. (true) Wake Angel's press count wasn't reset when the bridge's page joined again (the setting is per world). Fixed: counted afresh after a rejoin.
  4. (true) The "stopped" or "capped" note outlived a Wake (no new hello). Fixed: a Wake after a stop asks for a fresh hello, which clears the note (a bridge test counts the hellos).
  5. (true) Wake Angel couldn't bring back a handed-on turn, and was hidden while a chat had the turn. Fixed: a press on a handed-on turn gives it back to the API with a fresh event; Wake Angel and the note show while a chat has the turn because the API isn't listening.
  6. (true) "Nothing answered" stuck for the whole launch. Fixed: `wakeState` takes when the API last listened; a press it answered never reads as unanswered.
  7. (true) The hourly cap counted turns, not requests. Fixed: every request sent counts (the bridge test now caps at 5 with a three-try failure inside).
  8. (true) The History's total missed answers whose plans didn't land, and showed "under 1¢" for no price. Fixed: the worker keeps every answer's model and cost on the fight (`apiUse`), the total reads those, "0¢" and "no price known".
  9. (true) Any 400 mentioning "limit" stopped the worker. Fixed: only the credit balance, billing, a usage or a spend limit.
  10. (true) Changing the new-fights setting moved running fights. Fixed: a fight that starts with no route takes the setting's at that moment (`combatStart`).
  11. (true) A redirect could carry the key elsewhere. Fixed: `redirect: "error"`.
  12. (true) An unknown party level read as 1. Fixed: unknown stays unknown, and no caster counts as 2+ above then.
  13. (true) The risky paths had no tests. Added: module unit tests rt-16 (the hold) and wider rt-3, rt-5, rt-6, rt-7; bridge tests for the failure kinds and their words, the plan and cost helpers, a hand-in that throws, a fresh hello on Wake and the cap counting retries (154 in all). `firstEvent`, `offRoute` and `handOff` in the fight code still rest on the live checks rt-10 to rt-15.
  Its "checked and fine" list: the key never leaves the worker except to the API; the run loop can't start twice; handed-on choices keep their number; the skipped-turn filter keeps re-plans, a Delay's return, reactions, choices and stalls; generations per route; stalls to the chat; Wake answered before Play it myself's fall-through; text escaped; the Model row kept out of the profile drafting; the cost dedupe.
