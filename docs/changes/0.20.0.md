## Decisions made
- **The reaction timer (Rhea, 2026-11-09):** asked what range the world setting allows and whether 0 means no countdown, she chose "Option one, but only if a player has the right feat to get a reaction": 5 to 60 seconds, default 20, 0 = no countdown (the turn waits for the player or the GM's Continue); and a player is prompted only when their character has a reaction that fits the trigger. Rejected: 5 to 60 always timed; no timer at all.
- **Scope (Rhea, 2026-11-09):** asked whether to build player reactions as one release or two, she chose "Two: players first": 0.20.0 is players reacting during a monster's turn (every gate: leaving reach, a move that doesn't leave a square, manipulate and ranged, before an attack, on a hit before damage); monsters reacting on a player's turn is the next release. Rejected: both halves in one release.

<!-- The independent reviewer's findings, each marked verified true or false and what was done.
     Required when code changed; otherwise write `waived by Rhea <date>` with her reason. -->
Independent reviewer (a general-purpose agent that hadn't seen the work), 2026-11-09, on the diff, the feature doc and this record, before any live test. 25 findings; each read in the code (and the rules ones on Archives of Nethys) before acting:
1. A Crawl in reach was cancelled by its own gate (prone all along): **verified true**. Fixed: stop the move only if a reaction made it prone (`wasProne`).
2. A reload mid-gate left the turn stuck (asked, never done): **verified true**. Fixed: a reload keeps what was answered, skips the rest with a note, clears the question and closes the windows; the turn goes on.
3. A question left on the request after Play it myself (dead buttons, a redraw every second): **verified true**. Fixed: cleared on every way out; the countdown ticks only for the turn in hand while it runs.
4. Release triggered Reactive Strike: **verified true** (Archives of Nethys, Release: it doesn't trigger reactions that manipulate actions trigger). Fixed: Release asks nothing.
5. The AC re-read lost attack-only penalties (flanking) and could over-count: **verified true** (the code took the higher of the roll's DC and the actor's AC). Fixed: the attack's own DC plus what the new circumstance bonus beats (`circNow`). Open: a circumstance bonus that was only in the roll's DC (Visioner's cover) isn't known to `circNow`, so Nimble Dodge behind cover can add 2 it shouldn't (unverified item).
6. One answer per character for two reactions: **verified true**. Fixed: one row per reaction (`id` = token and slug), answers, windows and buttons keyed by it.
7. Nimble Dodge asked for spells and abilities but applied only to Strikes: **verified true**. Fixed: asked only for a Strike; spell attacks are an open item.
8. An error in a gate left the state "running": **verified true**. Fixed: every gate call caught; the turn stops with a note (or, at a hit, damage goes ahead with a note).
9. Waiting for a reaction looked like a machine stall: **verified true**. Fixed: `since` moves on when asking, and `stallOf` counts an open question as a person wait (`reacting`, 3 minutes); unit-tested.
10. The wait didn't notice the turn moving on: **verified true**. Fixed: it ends with `gone` when the fight, round or combatant changes; the turn stops with a note.
11. Hold during a gate didn't stop the action: **verified true**. Fixed for the question before an action and before a hit's damage (held there; Do it carries on); a move goes on to its end and holds before the next step (documented).
12. Whole-map answer writes could overwrite an answer arriving at the same time: **verified true**. Fixed: one key per answer.
13. The sender check fell back to the user the message claims: **verified true** in code. Fixed: the sender as Foundry reports it only; whether v14 passes it is checked live (r-9).
14. The critical-hit check compared two browsers' clocks: **verified true**. Fixed: attack rolls collected by the `createChatMessage` hook while the question is open.
15. Shield Block and Reactive Shield required seeing the monster: **verified true** (their triggers don't). Fixed: only Reactive Strike and Nimble Dodge need it.
16. A Climb was measured from where it ended: **verified true**. Fixed: measured from where it was. Stand is asked at the end of the action, as the design's rules line says; kept.
17. A reload could lose the Nimble Dodge degree (two saves): **verified true**. Fixed: one save.
18. Shield Block with automatic damage off wasn't told to the GM: **verified true**. Fixed: a note.
19. The runner's close made the window send a Pass: **verified true**. Fixed: closing by the runner marks it answered first, sends nothing.
20. Confused characters were asked: **verified true**. Fixed.
21. A disrupted step's cost: **verified true** (no word on slots). Fixed: the note says any slot or use is the GM's call.
22. `answerWords` unused, `GATES` unused, the doc's history claim: **verified true**. Fixed: the note uses `answerWords`; `GATES` gone; the doc no longer claims the history window shows reactions (it shows the step's note).
23. The hook check missed template-string hook names: **verified true**. Fixed: the unit test matches them too.
24. A Stand when already standing: **verified false** for plans (`checkPlan` refuses it). The GM's own rows now read "yours to answer".
25. Touch spell attacks count as ranged; abilities with the move trait aren't asked: **verified true**. Left as is (wording only for spells, nearly all of which are manipulate); listed in the feature doc's Open items.
Not checked by the reviewer: anything live, PF2e's `shieldBlockRequest` and Raise a Shield calls, the socket's sender argument, the DialogV2 order (checked by Angel in `foundry.mjs`: `submit` runs before close).
